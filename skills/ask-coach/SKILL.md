# /ask-coach 学习教练

ai-study-kit 的工具链很全（陪练教学 / 学习台 / 课程 / 闪卡 / 错题精讲 / 播客 / 升级），但工具全不等于知道「现在该干嘛」。**命令名即菜单**——敲 `/ask-coach` 就是问教练；本指令是主入口：先看状态，再给建议，最后带你执行。常用动作另有直入命令（陪练 `/study-coach`、体检 `/study-doctor`、错题串讲 `/study-recap`、播客 `/study-podcast`），其余走这里路由。

每次执行固定三步，不要跳步：

## Step 1 · 探测状态（永远先做；全程只读，≤1 分钟）

按 [`../../references/state.md`](../../references/state.md) 的探测协议采集下表各字段，拼成「学习状态快照」：

| 字段 | 回答的问题 |
|------|-----------|
| **学习项目** | 当前目录（或上次路径 / `~/study-kit`）是用户学习项目吗（判据 = 有 `examples/`）？`kit/` 是插件快照不算项目；旧形态 `kit/apps/quiz-app/` 照读但提示迁移（state.md §0） |
| **版本** | 轻布局项目没有 `kit/`：报「随插件 v<x>」+ 本体信号（插件快照 vs 最新发布：已最新 / 本体落后 → 先刷新插件 / 探测失败注一句）；旧项目残留 `kit/kit-version.json` 才比版本（落后 N 版 → F13）；仓库本体形态改探 git 落后程度（与 origin/main 同步 / 落后 N 提交 / 探测失败）。全部口径见 state.md §8 |
| **主题** | 当前主题是哪个（`progress.json` 的 `theme` 字段）？是演示还是用户自己的主题？主题 = `examples/<slug>/` 一个目录，见 state.md §1 |
| **库存** | 题库 N 题 · 闪卡 N 张 · 课程 N 节 · 错题串讲 N 簇 |
| **进度** | 已答 N/M · 未毕业错题 N · 到期闪卡 N · 课已学完 N/M（唯一来源 = 项目根 `progress.json`，口径 + 撤销墓碑见 state.md §3） |
| **计划** | 激活主题有带日程的学习计划吗（plan.json 可选）？完成 X/Y · 当前单元 · 落后/富余 ±N 天 · 断档 N 天（plan-report 确定性派生；无计划整行跳过，见 state.md §3）。断档 ≥ 3 天进入**回归场景**：`regression` 字段给热身一题 + 可重排建议（#125 升级为可执行重排，执行入口 `reschedule.command`，确认后写回 = 可否决）；`reschedule.view` 非空时报「已重排：下一站 X，日期 Y」（债务红字退场的宣告面，见 state.md §3「断档回归动作」与「重排判定与视图」） |
| **弱考点** | 考点掌握度报告怎么说（mastery-report 确定性派生：弱 N 个、最弱是谁；串讲档案记的错因一并带出；口头抽背的口头弱项也在此点名，见 state.md §3） |
| **陪练** | 有没有进行中的陪练站（站号·主题·待办数·模式）？距考期还有几天（deadline 未配置亮 ⚠）？三形态判定见 state.md §7 |
| **AI** | `.env` 的 LLM 三项配齐了吗（**绝不打印 key 的值**，只报 配齐/缺失） |
| **学习台** | 学习台连上项目了吗（右上「项目路径」= 本项目根？连上则顶部显示主题与已答数）；没有要起服务这回事（无 dev/server/pm2、无端口），见 state.md §5 |
| **意图** | 用户这句话里有没有明确想干的事（见下方意图路由表） |

仓库不存在时跳过其余探测，直接进 F1（bootstrap）。

## Step 2 · 汇报快照 + 推荐 + 菜单

用这个固定模板输出（数字全部来自 Step 1 实测，不许编）：


推荐行措辞纪律（细则单源 [`../../references/voice.md`](../../references/voice.md) §2）：**动作先行、依据可指认、禁空话**——「为什么」必须带 Step 1 实测数字或考点名（连错次数 / 到期张数 / 距考天数 / EP 编号）其一，「错题较多建议复习」式空话（任何状态都能套、报不出依据）不许出现。模板的行结构、emoji、菜单分组是扫读功能不算「话」，不受措辞纪律管辖。

### 推荐算法（用户没有明确意图时，按顺序取第一个命中的）

1. 仓库不存在 → **F1 初始化项目**（啥都没有，先把学习台连上）
2. 插件本体落后于最新发布（快照「版本」行本体信号；探测失败不命中本条，照走下面）→ **先引导刷新插件本体**（它是 F13 的前置——本体旧，F13 只会把项目对齐到旧快照，新功能照旧缺席；Route A/B 引导见 flows.md F13「插件更新节」）
3. 旧形态项目（根下有 `kit/`，快照「布局」行）→ **F13 迁移**（备份 → copy → 验计数 → 才删旧；轻布局项目没有这一条）
4. 激活主题是 `dev-intro`（演示内容），且用户有自己想学的东西 → **F2 开新主题**（demo 的 git/Linux 题不是学习材料）
5. 到期闪卡 > 0 → **F3 每日刷题**（先清复习——记忆在衰退，新知识可以等）
6. 有隔期复测候选（快照「隔期复测」行，`retest.pick` 非 null）→ **F10 陪练教学**（开场先复测这一项目标再进正题：`<EP-XX> 上次把 X 说错，口头 问 N 对 M，今天还没考过`——沿错因出 1-2 题短口述变体，并入第 0 步抽背位与到期卡同池合计 ≤3 题，复测完照常续站/开新站；零闪卡可用，不依赖 srsDue）
7. 距 MISSION.md 的 deadline ≤ 7 天 → **F11 考前冲刺**（短窗密集重复的窗口已开，这周巩固的边际收益压过学新；冲刺包不存在、或产包后又攒了新档案导致过期 → 先产包/重产。deadline 未配置则本条不命中——快照已亮 ⚠，用户走到 F11 入口再引导补）
8. 有进行中陪练站 → **F10 陪练教学** 续站（教到一半的站最该续——报站名 + 待办数，**用户点头才跑**：续站是建议不是指令，自动开跑是打扰）
9. 未毕业错题 ≥ 3 → **F4 错题串讲**（错题攒够了，值得 LLM 聚类深挖一轮。点名 mastery 报告最前的弱考点，档案里有错因就引用——理由从「错题多」具体到「EP-03 chmod 连错 2 次，错因：权限位组合不熟」；`oral.weakRanked` 里的口头弱项一并点名，无题知识点口头没到掌握线就再抽几轮）
10. 有未答题 且 课未学完（lessonsDone < 总数）→ **F3 每日刷题**（先建概念再做题——按当日课表读对应课；课在课程页点「✓ 学完了」才计数，打开不算）
11. 有未答题 且 课已学完（lessonsDone = 总数）→ **F3 每日刷题**（概念建齐了，直接刷题验效果）
12. 题全答完 且 正确率 ≥ 80% → **F5 做播客**（转被动巩固）或 **F2 开新主题**
13. 题全答完 且 正确率 < 80% → **F4 错题串讲**，仍不达标则 **F6 补课**（课程讲解质量不够）

顺序为什么是「刷本体 → 升级 → 闪卡 → 复测 → 冲刺 → 续站」：本体旧则一切升级都落在旧快照上（先刷新源再对齐项目，一趟到位），版本漂移是功能层在静默失血（升级保数据、一趟几分钟），复习是每天都欠的账（到期闪卡刷记忆，隔期复测验上次错的——复测并入 F10 开场抽背位，预算 ≤1 目标 × 1-2 题，不占独立时间槽），冲刺是 deadline 前一周的收割窗口，续站随时能续——六者的紧迫度就这么排（与 references/flows/F11.md 的档位一致）。

## Step 3 · 执行选定流程

读 [`references/flows.md`](references/flows.md) 中对应 playbook，逐步执行（其文件头有「流程 → 文件」目录：低频流程在 flows.md 本体；F4/F5/F6/F10/F11 高频流程拆在 [`references/flows/`](references/flows) 各自独立文件）：

- 每个流程末尾都有**完成标志**，达到才算完；达不到要如实说卡在哪。
- playbook 里的选择点（主题名、播客风格、改哪节课）才问用户；其余步骤直接做。
- 流程之间有接力：F2 完成接 F3 开始学；F4 读完串讲接「重做错题集」（错因根子是概念缺口的，交棒 F10 开补站）；F8 是内容自查（不是发布门，学习台没有发布这一步）；F10 阶段教完主动交棒 F3 刷对应题集；F11 冲刺包背熟交棒 F3 模考。

## 硬红线（执行任何流程前自查；下面六条即插件用户所需的全部红线，自足不依赖仓库文档。贡献者形态另有仓库级约定——官网 sync 产物、git 历史敏感等——见仓库 `AGENTS.md`）

1. 内容只改 `<项目>/examples/<theme>/` 里的源文件——学习台**直读**它，改完刷新即生效，没有同步产物、没有 build。`<插件根>/kit/` 是插件自带的内容工具快照，**不是用户项目**，往里写数据等于写到安装目录里。
2. `<项目>/progress.json` 是**运行期数据**（项目根一份，主题只是它里面的一个选择）：禁止手编；需要清进度用学习台内的重置入口，绝不手改文件。写坏的进度文件数据层会拒绝覆盖并报错——别对用户说「已自动重置」。
3. 切换主题在学习台顶栏点一下即可（当前主题记进 `progress.json` 的 `theme` 字段，**没有环境变量要改**）；首页分组/显示名等呈现定制走主题包的 `theme-config.json`（可选文件，缺什么回退什么、绝不出错；常用字段：显示名 `topicLabels`、分组顺序 `topicOrder`、子主题 `subtopics`、课→题集直达 `lessonTopics`；示例照 `<插件根>/kit/examples/dev-intro/theme-config.json`）。
4. 产内容（课程/题/闪卡/笔记）时**不许出现真实企业品牌名**，一律中性化（「某车企」「某大厂」或删例）；技术专名（开源技术栈）可保留。`pnpm run scan` 是插件仓库的开发态扫描脚本，学习项目里没有它——agent 按这条口径自己核，别派给学习者。
5. 多选题判分是**全对才算对**；改题尽量保留旧题 id（进度按 id 存，换 id 会丢进度）。
