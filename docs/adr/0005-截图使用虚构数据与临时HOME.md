# 0005 官网截图用虚构示例数据与临时 DSH_HOME

## 状态

已采纳（2026-11-16）

## 上下文

官网需要插件在 DSH 里的真实截图，用户明确要求「别把我个人信息截出去」。

真实截图里的敏感面不止一类：

- 学习内容本身：真实主题名（如软考科目）、真实题干与解析、真实错题与正确率、`plan.deadline`
- 环境信息：DSH 侧栏的会话列表与标题、最近打开的工区路径、用户名
- 其他插件：`~/.dsh/profiles/web` 里装的第三方插件（如 dsh-wewrite、dsh-web-ui 全家桶）会出现在插件管理页与侧栏

事后打码只有「漏一处就泄露」的风险，而且题干里可能带专业痕迹，肉眼判断不可靠。

现成素材：`kit/examples/dev-intro/` 是纯虚构示例主题（`MISSION.md` 明写虚构、与专业领域零耦合，git/Linux 入门，10 题 4 卡）。

## 决定

截图**不使用真实数据**：

1. 建临时学习项目（只含 `examples/dev-intro` + 空 `progress.json`），路径在 `/tmp` 下。
2. `DSH_HOME` 指向临时目录再起 `dsh web`，会话列表、插件列表、凭据、存储全部是空的——真实 profile 一个字都不进画面。
3. 用 Playwright 真 Chromium 实拍，viewport 1440×900、`deviceScaleFactor: 2`、locale `zh-CN`、全页 PNG。

播种脚本**绝不能**写用户的 `~/.dsh/storages/`（dsh-wewrite 的 seed 脚本就是这么写的，直接覆盖真实存储；照抄时必须先隔离 HOME）。

## 后果

- 好处：泄露面从「不可枚举的真实文本」变成「零」——画面里所有内容都是仓库里已公开的虚构素材。
- 代价：截图里的学习记录是假数据，不能展示「学了很多」的说服力。接受：官网主打的是插件形态与工作流，不是战绩。
- 代价：每次重拍都要重建临时环境，因此固化成一个脚本（`scripts/screenshots/`），而不是手工操作。

## 备选方案

- **真实项目 + 事后打码**：否决，靠肉眼逐处遮挡不可靠。
- **真实项目但换一个能公开的备考主题、真学几天再拍**：否决，把交付时间绑在学习进度上。
