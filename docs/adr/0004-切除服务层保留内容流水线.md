# 0004 切除服务层，保留内容流水线

## 状态

已采纳（2026-11-16）

## 上下文

旧形态里 `pnpm` 承担两类完全不同的职责，很容易被当成一件事：

| 用途 | 命令 | 是谁的事 |
|---|---|---|
| 起站点 | `pnpm dev`、`pnpm run server`、pm2 `ecosystem.config.cjs`（:8787） | 用户 |
| 内容流水线 | `pnpm run scan`、`pnpm test`、`pnpm run build`、`pnpm run check:alignment` | 开发者（改题/改内容时） |

集成后页面由 DSH 插件提供，Host 半直接供数，:8787 那套 Hono 服务不再有任何调用方。

## 决定

- **切除服务层**：`server/`、`pnpm dev`、`pnpm run server`、pm2 部署、`:8787` 健康检查，全部从 skill 正文里去掉。skill 里「后端在线」的判据改成「学习台可用」（即插件装着、项目探测得到）。
- **保留内容流水线**：`scan` / `test` / `build` / `check:alignment` 留在 kit 仓库形态里，skill 的 F8（五门校验）、F13（升级）继续引用，但明确标注「只有维护内容时才跑」。
- 测试的 `AI_STUDY_KIT_SRC` 逐字节比对改成「已记录差异白名单 diff」。

## 后果

- 好处：新用户完全不用碰 pnpm；改界面/改内容的人才需要。
- 好处：排障表里「课程白屏 / 进度丢 / 改题不生效 / grill 拉不到错题」四类里有三类原因消失（都源于服务与产物）。
- 代价：**旧站 UI（`kit/apps/quiz-app/src`，3269 行页面 + 1397 行组件）在集成后没有调用方**。按用户的判断，装了插件的人不会再打开老站，因此页面源码只保留插件里的一份，`kit/apps/quiz-app` 只留内容工具链。开发 UI 从此没有 vite 热更新，走插件的 build + 重装回路（`npm run dev:install`，照 dsh-wewrite）。
- 代价：skill 正文大范围改写，与上游 `ai-study-kit` 的快照一致性丢失——这是刻意的，`docs/DETAIL.md` §4 记录差异。

## 备选方案

- **保留服务层作为可选后备**：否决，双份实现必然腐化，且用户不需要。
- **把内容流水线也搬进插件**：否决，那是开发者工具，不该进用户安装包（`files` 里 `kit/` 已经是负担，再塞 node 工具链更重）。
