# 0003 用户学习项目统一为轻结构，旧结构一次性迁移

## 状态

已采纳（2026-11-16）

## 上下文

集成前，用户拿到学习项目的方式是 `cp -r <插件根>/kit ~/study-kit/kit` 再 `npm install`，于是「项目」= 一份完整 kit 拷贝：`node_modules/`、`src/`、`public/`、`server/`、`scripts/`、`examples/`、`progress.json`。页面真正需要的只有 `examples/<theme>/` 和 `progress.json`。

集成后不再需要 `npm install`、不再需要起服务、不再需要 build，所以「项目必须是完整 kit」这个前提消失了，只剩历史包袱：旧项目的数据在 `kit/apps/quiz-app/` 下面。

当时的选项是「两种都认」和「统一成一种」。用户明确要求目录统一——两种都认意味着探测逻辑、文档、迁移提示、报错文案都要双份，而且 agent 每次都得先判断自己是哪种。

## 决定

统一为轻结构：

```
<项目根>/examples/<theme>/     # 主题数据
<项目根>/progress.json         # 进度真源
<项目根>/study/                # 私有记录
```

探测顺序：会话 cwd → 上次记住的路径 → `~/study-kit` → 弹目录选择器。

**旧结构只用于识别与迁移**：探测到 `kit/apps/quiz-app/examples/` 时提示迁移，由 agent 执行「copy → 校验题目条数与 answers 条数 → 才删原件」，并先留一份备份。

## 后果

- 好处：目录语义正确（这是数据目录，不是仓库）；与 kit 仓库的判据不再混（项目没有 `package.json`，仓库有 `package.json name=ai-study-kit` 或 `AGENTS.md`）。
- 好处：新项目创建极轻，迁移脚本只有一条路径。
- 代价：**存量项目必须搬一次**。这是唯一不可逆的代价，所以迁移必须可回退（先 copy、校验、再删，且保留备份）。
- 代价：`skills/ask-coach/references/state.md` §0 的「找仓库」判据、`flows.md` 里所有 `kit/apps/quiz-app/...` 路径要同步改写，且 `test/plugin.test.mjs` 的逐字节比对要改成「已记录差异白名单」（`docs/DETAIL.md` 已有先例）。

## 备选方案

- **两种结构都认**：否决，用户要求统一；双探测逻辑长期腐化。
- **统一到 `kit/apps/quiz-app/`**：否决，路径名对用户无意义，且会让人以为必须装 kit。
