# 0001 学习台注册为 main 面板，不注册会话 tab

## 状态

已采纳（2026-11-16）

## 上下文

把答题站搬进 DSH 后，第一个问题是「它长在 DSH 的哪个位子上」。手边有两个现成先例：

- **dsh-wewrite** 用 `conversation.view`：在会话页顶部加一个 tab，与「对话」「轨迹」并排。
- **官方 Plugins / Schedule** 用 `main` 槽 + `sidebar.panellist`：一个全局功能页，从侧栏图标进入。

`main` 槽的契约原文（`dsh-client-ui-layout/lib/types/client/index.d.ts`）：

> Central panel selected by sidebar entry id. The reserved `conversation` key hosts the Conversation; **other keys receive no Session binding.**

而 `conversation.view` 的语义是「这个会话里的另一个视图」，`inject` 拿到的是 `sessionId`。

学习进度是全局的：同一份 `progress.json`，在哪开会话打开都一样。挂到会话 tab 上等于宣称「进度属于这个会话」，语义是错的；而且用户想看学习台得先有一个会话，在空会话列表里反而没入口。

## 决定

学习台注册为 `main` 面板（`key: 'ai-study-kit'`），配 `sidebar.panellist` 图标入口，`order` 排在官方 Plugins/Schedule 之后。**不注册** `conversation.view`。

## 后果

- 好处：语义正确；空会话也能进；和官方功能页形态一致。
- 代价：没有 `sessionId`，因此拿不到「当前会话上下文」——这是刻意的，学习台不该依赖会话。
- 代价：使用频率低的入口会一直占侧栏一个图标位。可接受，因为侧栏本来就是放功能入口的地方。
- 模板照 `dsh-client-ui-schedule/lib/client.js` 的两行注册写法；两处都必须先 `ctx.slots.inject(name, fn)` 再 `register`，否则向未声明槽注册会抛异常。

## 备选方案

- **会话页 tab（wewrite 形态）**：否决，语义错位，且空会话无入口。
- **`shell.overlay` 浮层**：否决，学习台是长时间停留的页面，浮层适合短交互。
- **两个都注册**：否决，同一功能两个入口要维护两套状态与截图。
